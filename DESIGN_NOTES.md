# DESIGN_NOTES - Agent Academy (working name)

Status: written 2026-10-15 before any CSS. Hex values are estimated by eye from the 800px webp previews (not pulled from source CSS); they get re-checked against the real build.
Process followed: site-plan.md section 2.4 sample course -> UI Hub (data.json clustered, previews opened) -> frontend-design + taste-skill + impeccable rules -> emil-design-eng / UI Hub kb/spec/motion.md for motion -> self-check.

## Design read (one line)
A campus catalogue for agents: a dense, editorial bento index where each profession is a grain-gradient "faculty" tile, crowned by a slowly turning academy seal, set in a wide heavy grotesk. Mode (impeccable): Read + Operate (browse and copy), not Persuade.

Type:
- Display: **Archivo** variable (wdth 62-125, wght 100-900), set expanded (wdth 112-125) weight 800 for headlines and the wordmark, condensed (wdth 75) for big counters. Echoes the Codrops/Skiper wide heavy grotesk. Not Inter, not Fraunces/Instrument (banned by taste-skill).
- Body/UI: **Geist** variable 400/500/600, 15px body, 1.6 line-height, max 72ch.
- Code only: **Geist Mono** for install commands and endpoint paths (real code, not decorative data labels).
- CJK falls back to system (PingFang SC/TC, Hiragino, Apple SD Gothic Neo, Noto Sans CJK); Vietnamese diacritics covered by Geist/Archivo latin-ext.
- Rules: sentence case everywhere, no all-caps labels, no em dash in copy, no "01/02" except the real 5-step course order and the real newest-first stack.

Radius scale (by hierarchy, not one value): faculty tiles 14px, resource tiles 8px, chips 6px, pills 999px, seal circle.
Shadow: none on cards (color blocks and 1px lines carry depth); one soft shadow only on the fanned stack.
Spacing: 4px base; card padding is one token `--pad: 18px` (mobile 16px) used by every card type; gaps 12/16/24/40.

## 6. Motion budget (one orchestrated moment per page + responsive feedback)
| motion | where | spec | reduced-motion |
|---|---|---|---|
| seal rotation | hero emblem | 48s linear infinite rotate, pauses offscreen (IntersectionObserver) | static |
| line-wave drift | hero background | 2 SVG stroke bundles, translateX/rotate 18s ease-in-out alternate | static |
| fanned stack | hero latest additions | rest: rotated -6..6deg stacked; hover/focus: spread translateY, 260ms cubic-bezier(.2,.8,.2,1) | no transform, plain list |
| grain gradient drift | faculty tiles | background-position 0 -> 40% on hover, 600ms ease-out; petals rotate 8deg spring | color only |
| pipeline traveler | course path | highlight steps every 1.6s once when scrolled into view, then stops; click to select | first step selected |
| number ticker | counts | count-up 900ms ease-out once | final number |
| page transitions | all pages | `@view-transition { navigation: auto }` 220ms fade | none |
Only transform/opacity/background-position animate. No scroll listeners (IntersectionObserver only).

## 8. Anti-overflow + consistency rules (hard)
- Every URL, repo path, install command: `overflow-wrap:anywhere; word-break:break-word` and code blocks `white-space:pre-wrap`.
- Titles clamp to 2 lines, summaries to 3 on tiles; full text on detail page.
- One card padding token for all cards; tiles in a grid row share height (grid `align-items:stretch`), actions pinned to the bottom.

## 9. Direction change (2026-10-15, confirmed by the user via the parent agent)
1. The core interaction is a **prompt generator**, placed as a prominent **Quick start** module (not the whole page): pick or type the bot you want, profession and role, preferences (design style, reply language, platform) -> one copyable prompt that points to raw files in the GitHub repo (course.md, SKILL.md mirrors, role JSON).
2. The home page itself stays **fancy**: animated background, bento showcase, course and industry visualisations, a live "Latest added" feed from real data, and the design-course before/after case.
3. The design course is the thickest course and is wired to UI Hub data (api/resources.json, ~2,391 items); this site's own design process is its first case.
4. Template library = permissively licensed SKILL.md files + prompts.chat CC0 prompts + BotsDots directory, each with license + source link. Industries without a course show "Coming soon" (localised).
5. Every card shows two safety tags: needs credentials? sends externally?

## 11. Redo (r4): three palette + component directions, every module from a UI Hub component
Rules applied to all three: neutral ramp + ONE accent (kb/spec colour rule; semantic tokens; text contrast >= 4.5:1; dark = off-black base + lighter accent + `color-scheme`); no rainbow, no colour slabs. Every module is a vanilla port of the registry source in `directions/orig/src/*.tsx` (class values, durations, springs and easings copied, not invented). Skills followed: taste-skill (one accent, dense refined cards, no generic hero gradients), frontend-design (one orchestrated motion moment per section, real content, no lorem), emil-design-eng (transform/opacity-only motion, 150-400 ms UI feedback, springs for selection, reduced-motion fallbacks).
Shared: wizard = 3 selection-only steps (bot icon cards + custom input -> role -> style cards with real UI Hub thumbnails, platform cards Cursor / Claude Code / Codex / Grok Bot / Other, language chips) with a light "Selected / 已选" chip summary, no live prompt; Generate reveals (1) a terminal/code card that typewrites the prompt with line numbers + syntax colour (click to skip), (2) file mini-cards wired to the agent node with Animated Beam lines, (3) copy button with success animation; "Start over / 重新选" returns to the steps. "Open in Cursor" uses Cursor's documented deeplink `https://cursor.com/link/prompt?text=` (shown only when platform = Cursor and the prompt is <= 8,000 chars). Claude Code has no documented prompt deeplink, so no button. Platform tiles are text monograms, not trademark logos.

## 12. Full site (r5): one site, three switchable styles
The user picked **A (Zinc + Indigo, minimal)** as the default and kept **B (black + Emerald, dark-tech)** and **C (warm stone + Rose, editorial)** as in-site themes (2026-10-15).

How it works
- `<html data-skin="a|b|c">` is set by an inline head script before first paint: `?skin=` → `localStorage["aa-skin"]` → `a`. Light/dark is independent: `?theme=` → `localStorage["aa-theme"]` → `prefers-color-scheme`. No flash: CSS for all three skins is in `assets/site.css`, scoped by PostCSS (`scripts/scope-css.mjs`: `:root` → `:root[data-skin=x]`, `.dark` → `[data-skin=x].dark`, every other selector prefixed `[data-skin=x]`).
- Each skin keeps its own tokens (`--bg --card --line --ink --muted --acc …`), fonts and signature modules: A Flickering Grid headers + Magic Card roles + shadcn Tabs nav; B Floating Dock nav + Background Beams headers + React Bits Spotlight Card cards and roles; C Instrument Serif headlines + Hero Highlight dots + Direction Aware Tabs nav + 3D Card roles.
- Home: the A `<main>` is real DOM; the B and C mains sit in `<template>` and an inline script swaps them in before paint when the skin is not A. Switching on the home page reloads; on inner pages it switches in place.
- Inner pages: `src/pages.css` is written once against the shared tokens and re-skinned with `[data-skin=x]` overrides (radius, card treatment, title font, header background). One card padding (20px) everywhere; long URLs wrap (`overflow-wrap:anywhere`).
- Switcher: top-right **A · B · C** toggle group (next to the language select and the light/dark toggle). Shareable: add `?skin=b` to any URL.
- Machine-readable table: `directions/mapping.mjs` (`SITE_MAP`), rendered at https://siinxu.github.io/agent-academy/directions/.
- Deviations from the originals: Background Beams start delay 0–2.5 s (original 0–10 s) so beams show on short visits; Flickering Grid redraws at ~16 fps and only while on screen (same flicker maths) to keep mobile main-thread time down.

## 13. Original content on resource pages (r5.3)
Every resource page now has an **Original content** section (`#original`). What it shows is decided per item by its license (`scripts/originals.py`, run daily after `collect.py`; output `data/originals.json` + `data/originals/<id>.md`):

| Source | License situation | What the page shows |
|---|---|---|
| GitHub skills / prompts / workflows (`data/mirror`) | MIT, Apache-2.0, CC0, CC-BY, BSD, ISC | Full original text (prose), attribution + license + source link |
| prompts.chat | CC0-1.0 | Full prompt in a Code Block with a copy button |
| MCP Registry servers with a GitHub repo under a permissive license | MIT / Apache-2.0 / ISC / CC0 | Full repository README (HTML/badges stripped) + the registry record |
| MCP Registry servers, license not stated or not permissive | — | Public registry record (description, version, packages, env var names, remotes, website); docs not republished |
| BotsDots templates | catalog record CC0-1.0; the bot belongs to its creator | Complete catalog record (description, category, schedule, access, integrations, creator, first listed, catalogs, x.ai link); the bot's instructions are not republished |
| UI Hub entries with a GitHub repo under a permissive license | checked via the GitHub API | Full README |
| Other UI Hub entries | the linked site's own terms | The UI Hub entry (our description) + link |
| Seed items (Apple HIG, Material 3, WCAG, …) | site terms / W3C license | Link-only notice |

Rules: nothing behind a login is fetched; READMEs are capped at 60,000 characters (the page says so); long texts open with the Collapsible trigger. The `r/<id>.md`, `api/resources/<id>.json` (`original` field) and course packs carry the same texts for agents.

Translations: resource summaries are shown in the language they were written in, labelled "Original · English" (or 中文 …) when the page language differs. Offline Argos machine translations produced nonsense too often (e.g. the SEO & AEO Desk summary in Chinese), so they are no longer displayed; the only conversion kept is OpenCC zh-CN → zh-TW for texts written in Chinese. Course goals, permissions and checklists (28 texts) were translated by hand into the 9 other languages (`by: "agent"` in `data/l10n`, which `translate.py` never overwrites).
