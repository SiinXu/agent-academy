# PostHog MCP Server

The Sprites MCP server connects PostHog to Claude, ChatGPT and any MCP client, read-only. Ask a product question and Sprites queries your project and answers by the campaign, source or click ID that brought each session in — in the same conversation as the ad account that paid for the click.

1. **Connect PostHog in Sprites.** Sign up at [sprites.ai](https://www.sprites.ai) and connect PostHog once in the Sprites integrations menu. Start a trial from the Sprites site.

## Setup by client

### Claude (claude.ai and Claude Desktop)

Works on Free (one custom connector), Pro, Max, Team and Enterprise.

1. Settings, then Customize, then Connectors. On Team and Enterprise an Owner adds it once under Organization settings, Connectors.
2. Click **+**, then **Add custom connector**. Name it `Sprites` and paste `https://mcp.sprites.ai/mcp`. Leave Advanced settings empty.
3. Click **Connect**, sign in to Sprites and approve.

Claude draws the Sprites approval card in the chat, so you can edit a budget or a headline in place and approve it.

### Claude Code

```bash
claude mcp add --transport http sprites https://mcp.sprites.ai/mcp
```

Then type `/mcp` inside Claude Code to finish the browser sign-in.

### ChatGPT

Plus, Pro, Business, Enterprise and Edu, on the web app. Not available on Free.

1. Settings, Security and login: turn on **Developer mode**. On Business and Enterprise an admin has to allow it first.
2. Settings, **Plugins** (formerly Connectors), then **+** to create an app.
3. Name `Sprites`, MCP server URL `https://mcp.sprites.ai/mcp`, Authentication **OAuth**. Tick the trust box and click Create.
4. Connect the app and sign in to Sprites.

### Cursor

`~/.cursor/mcp.json` (every project) or `.cursor/mcp.json` (one repo):

```json
{
  "mcpServers": {
    "sprites": {
      "url": "https://mcp.sprites.ai/mcp"
    }
  }
}
```

Cursor discovers the Sprites authorization server from the endpoint and opens a browser to sign in.

### Codex

```bash
codex mcp add sprites --url https://mcp.sprites.ai/mcp
codex mcp login sprites
```

Or by hand in `~/.codex/config.toml`:

```toml
[mcp_servers.sprites]
url = "https://mcp.sprites.ai/mcp"
auth = "oauth"
```

### VS Code and GitHub Copilot

`.vscode/mcp.json`. The top-level key is `servers`, not `mcpServers`, and a remote server needs `"type": "http"`:

```json
{
  "servers": {
    "sprites": {
      "type": "http",
      "url": "https://mcp.sprites.ai/mcp"
    }
  }
}
```

Run **Auth** above the entry, sign in, then switch Copilot Chat to **Agent** mode. Ask mode does not call MCP tools.

### Gemini CLI

`~/.gemini/settings.json`. Use `httpUrl`; a `url` entry is treated as SSE:

```json
{
  "mcpServers": {
    "sprites": {
      "httpUrl": "https://mcp.sprites.ai/mcp"
    }
  }
}
```

Restart the CLI; the first call opens the sign-in. Check with `gemini mcp list`.

## What it can read

- Events, their 30-day volume and reach, and property keys
- Saved insights, feature flags, cohorts and actions — listed, not changed
- Trends, breakdowns, funnels and retention computed from your events
- Session attribution: entry UTM parameters, gclid, fbclid, referring domain and channel type
- The project timezone and its internal and test-user filter

## What it can change (with your approval)

- Nothing in PostHog. Every PostHog tool is read-only.
- Changes the analysis leads to — a budget, a paused ad set — happen in the ad account, each as an approval card

Every change arrives as an approval with the before and after. In Claude and ChatGPT it is a card you can edit
in place. In clients without cards, Sprites returns the change written out with a gate id, and applies it only
after you confirm (`approve_change`). Nothing is applied by the model on its own.

## Permissions

- **Personal API key.** Created in your PostHog account settings, with its scopes chosen per key.
- **Project.** Every query runs against one project, on the US or the EU cloud.
- **What Sprites asks for.** A personal API key and the project you select, held by Sprites.
- **What you skip.** The key never sits in your AI client’s config. Sprites holds it, and your agent signs in to Sprites with OAuth.
- **Your AI client never holds a platform credential.** It holds a Sprites OAuth token bound to `https://mcp.sprites.ai/mcp`.

## Tools

The server exposes 20 tools to the model: 6 read tools and 14 write tools. Write tools that touch an ad account or a site only propose; nothing reaches either until you approve it. The tools that do the PostHog work:

| Tool | What it does on PostHog |
|---|---|
| `analyze` | Trends, breakdowns, funnels and retention computed from your PostHog events. |
| `optimize` | Ad spend judged by what those visitors did afterwards, with the fix as an approval. |
| `research` | What the project actually tracks: events, volumes, properties, flags and cohorts. |
| `schedule_task` | A weekly funnel or activation read, delivered on its own. |

PostHog requests use `channel: seo_web`. Name another channel, or `all`, to compare.

Every task tool takes the same input: `goal` (the request written to stand on its own: Sprites sees only this
string, not the chat), `title` (a short label), `channel`, and `today` (the user's local date, so "last 30 days"
resolves correctly). Long tasks return a run id; `task_status` collects the result and `cancel_task` stops it.

## FAQ

**Is this a server I have to host?**
No. It is a hosted remote MCP server. Paste `https://mcp.sprites.ai/mcp` into your client and sign in.

**How does it compare with other PostHog MCP servers?**
PostHog hosts its own MCP server at mcp.posthog.com/mcp, free to call. It reaches most of PostHog (insights and SQL, dashboards, experiments, feature flags, surveys and error tracking) and it reads and writes. PostHog’s server is open source and lives in PostHog’s own repository, so the open-source route and the official one are the same code. Neither sees what the traffic cost. Sprites reads PostHog trends, funnels, retention and session attribution (UTMs, gclid, fbclid) and sets them beside Google Ads, Meta, LinkedIn, TikTok and Reddit spend. It writes nothing in PostHog; the change the analysis leads to happens in the ad account, as an approval card.

**Is there an official PostHog MCP server?**
Yes. PostHog runs its own hosted server at https://mcp.posthog.com/mcp, signed in with PostHog OAuth or a personal API key, and installable with npx @posthog/wizard mcp add. It reads and writes across insights, dashboards, SQL, feature flags, experiments, surveys and error tracking. Calling it is free; tools that use an LLM inside PostHog bill as PostHog AI.

**What is the difference between that and Sprites?**
PostHog’s server is PostHog, all of it, including the ability to change flags and dashboards. Sprites reads PostHog only, and puts it beside your ad accounts: the same specialist that reads Google Ads or Meta reads the funnel, so it can say which campaign brings users who activate — and propose the budget change.

**Can Sprites change anything in PostHog?**
No. Both PostHog tools are read-only: Sprites queries events and reads configuration, and never creates, edits or deletes a flag, insight, dashboard or experiment.

**How does Sprites connect to PostHog?**
With a PostHog personal API key and the project you select, on the US or EU cloud. The key is held by Sprites, not by your AI client, so it never sits in a config file on your machine.

**Can it break results down by UTM campaign?**
Yes. Breakdowns can use the session’s entry UTM source, medium, campaign, term and content, its gclid or fbclid, the referring domain or the channel type — the fields that tie a session to the ad that bought it.

**Does it exclude internal and test users?**
It applies the project’s own internal and test-user filter by default, and every answer says whether that filter exists. If it does not, you are told rather than shown numbers that include your team.

**Which agents can I use it from?**
Claude, ChatGPT, Codex, Cursor, Gemini, Grok and any other client that speaks remote MCP. One endpoint, one sign-in, and PostHog is connected once inside Sprites.

**Does it cover other channels?**
Yes. The same URL reaches Google Ads, Meta Ads, LinkedIn Ads, TikTok Ads, Reddit Ads, Microsoft Advertising,
Apple Ads, GA4, Search Console, Shopify, SEO and AI visibility, and Google Business Profile, for whatever is
connected in Sprites. See [ads-mcp-servers](https://github.com/sprites-ai/ads-mcp-servers).

**How much does it cost?**
The connector is included in every Sprites plan, and every plan starts with a short trial. See sprites.ai for current plans. PostHog is billed by its own vendor as usual.

**The client says it has no tools, or every call is unauthorized.**
Remove the server, re-add it with exactly `https://mcp.sprites.ai/mcp`, and sign in again. Grants are bound to that one URL.

**How do I revoke access?**
Disconnect the connector in your client, or remove the connection in Sprites. The next tool call fails closed.
